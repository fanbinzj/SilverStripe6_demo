# Stage 3: Stock Profiles and Search (Routing, Controllers, Forms)

## What was built

```
/stocks?q=snd             search results; an exact ticker match redirects to the profile
/stocks/SNDL              stock profile (fundamentals, dilution, ownership, background, dates)
/stocks/sndl              301 -> /stocks/SNDL
/stocks/NOPE              404
/stocks/ReportForm        POST target of the "Report a data issue" form
```

| Piece | File |
|---|---|
| Routing and actions | `app/src/Pages/StockDirectoryPageController.php` |
| Search service | `app/src/Search/StockSearch.php` |
| Report model | `app/src/Model/DataIssueReport.php` (listed in Market data admin) |

Profiles show "Not available" for anything not imported yet; stage 4 fills in the data.

## 1. Routing: a page controller that serves many URLs

Stocks are DataObjects, not pages, so one page (`/stocks`) handles every profile through its controller:

```php
private static $allowed_actions = ['stock', 'ReportForm'];

private static $url_handlers = [
    'ReportForm' => 'ReportForm',   // specific rule first
    '$Ticker!' => 'stock',          // catch-all: /stocks/ANYTHING
];
```

- The request path after the page URL is matched against `$url_handlers` **in order**; the first match wins. If
  `$Ticker!` came first, `/stocks/ReportForm` would be treated as a ticker.
- `$Ticker` becomes a URL parameter: `$request->param('Ticker')`. `!` makes it required, so `/stocks` alone still
  goes to `index()`.
- Every target must be in `$allowed_actions`.

### Status codes

| Situation | Response | Why |
|---|---|---|
| Unknown ticker | `$this->httpError(404)` | Renders the CMS "Page not found" page with a 404 status |
| Lower-case ticker | `$this->redirect($stock->Link(), 301)` | One canonical URL per stock (better for SEO and caching) |
| Exact ticker searched | `$this->redirect(...)` (302) | Temporary: depends on the query, not a permanent move |
| Form posted for an unknown stock | `httpError(400)` | Bad request |

### Action templates

The `stock` action renders `StockDirectoryPage_stock.ss` if it exists, falling back to `StockDirectoryPage.ss`.
Returning an array from an action adds values to the template scope; returning `Title` overrides the page's own
title, so the browser tab reads "SNDL: SNDL Inc. | PennyMirror".

This does **not** work for the meta description: `$MetaTags` is generated by the page record itself and ignores
the template scope. The controller sets `$this->data()->MetaDescription` on the in-memory record instead (it is
never written). A good example of checking where a template variable actually comes from.

### Model links

`Stock::Link()` builds `/stocks/TICKER` from the directory page. Because it runs for every stock in a list,
`StockDirectoryPage::get_instance()` caches the page lookup for the request instead of querying each time.

## 2. Dependency injection in a controller

```php
private static $dependencies = [
    'search' => '%$' . StockSearch::class,
];

public function setSearch(StockSearch $search): static { ... }
```

Page controllers are created with `Injector::inst()->create()` (see `ModelAsController`), so the Injector reads
`$dependencies` and calls `setSearch()` with a `StockSearch` instance. The `%$` prefix means "an Injector service".
A different implementation can be swapped in via YAML, or a fake one set in tests, without changing the controller.

## 3. The search service and SQL safety

`StockSearch` ranks ticker prefix matches first (shortest ticker first), then company name matches. It uses two ORM
queries instead of one query with `ORDER BY CASE WHEN "Ticker" = '...'`:

- ORM filters (`filter('Ticker:StartsWith', $q)`) use parameterised queries, so user input is never part of the SQL
  text.
- A ranking `ORDER BY` would need the search term inside raw SQL via `DataList::orderBy()`, which the framework
  documents as open to SQL injection if misused.
- Tickers are short and results are capped (50), so doing the final ordering in PHP costs nothing noticeable.

`exclude('ID', $ids)` keeps name matches from repeating ticker matches.

## 4. Templates

### Includes with arguments

```html
<% include Fact Label="Cash", Value=$CashNice, AsOf=$CashAsOf %>
```

The include receives `$Label`, `$Value` and `$AsOf` on top of the current scope. `Fact.ss` prints "Not available"
when `AsOf` is empty, which implements the "unknown is not zero" rule from stage 2 in one place.

### Scope

`<% with $Stock %> ... <% end_with %>` makes the stock the scope, so `$Ticker` means `$Stock.Ticker`. The report
form is rendered **outside** that block, because `$ReportForm` is a method on the controller, not the stock.

### Formatting

- `$SharesOutstanding.Formatted` → `49,750,000` (DBInt method).
- `$FiledDate.Nice`, `$UsedFrom.Year` → date field methods.
- Money uses methods on the model (`getCashNice()`, `getLastPriceNice()`) because the rules are domain specific:
  compact "$4.2M" for large numbers, 4 decimal places for sub-dollar prices, and nothing when the value is unknown.

### Accessibility

Each section is a `<section>` labelled by its heading (`aria-labelledby`); the table has a caption and `scope="col"`
headers; "View filing" links carry visually hidden context ("424B5 Sep 1, 2026") so screen reader users hearing a
list of links know which filing each one opens.

## 5. Forms

```php
public function ReportForm(): Form
{
    $fields = FieldList::create(
        HiddenField::create('StockID', null, $this->stock?->ID),
        TextareaField::create('Message', 'What looks wrong?'),
        EmailField::create('Email', 'Your email (optional)')
    );
    $actions = FieldList::create(FormAction::create('doReport', 'Send report'));
    return Form::create($this, 'ReportForm', $fields, $actions, RequiredFieldsValidator::create(['Message']));
}
```

- **The form is itself a URL**: `Form::create($this, 'ReportForm', ...)` makes the form post to
  `/stocks/ReportForm`, which is why `ReportForm` is in `$allowed_actions` and `$url_handlers`.
- **Action handlers** (`doReport`) are not in `$allowed_actions`. The form only runs actions it contains.
- **CSRF protection** is on by default: every form has a hidden `SecurityID` token tied to the session. A POST
  without it is rejected with 400.
- **Validation** runs before the handler. `RequiredFieldsValidator` (renamed from `RequiredFields` in CMS 6) checks
  required fields; `EmailField` validates the email format. On failure the visitor is sent back with their input and
  error messages kept in the session.
- **`DataIssueReport::validate()`** checks the same rules at the model level (message length, linked stock), so
  they also apply to records created anywhere else.
- **Mass assignment**: `$form->saveInto($report)` only copies fields that exist on the form. Adding
  `Status=Resolved` to the POST data does nothing.
- **Post/Redirect/Get**: after saving, the handler sets `$form->sessionMessage(...)` and redirects, so refreshing
  the page doesn't resubmit the form.
- **Hidden fields are user input**: `StockID` is re-checked with `Stock::get()->byID()` rather than trusted.

## 6. Permissions on the report model

`DataIssueReport` uses the market data permission trait but overrides `canView()`: reports contain visitors' email
addresses, so they are only visible to CMS users who can manage market data. The public form creates reports from
the controller, which does not depend on `canCreate()`.

## 8. Self-check Q&A

1. **Why does the order of `$url_handlers` matter?**
   Rules are checked top to bottom and the first match wins; a catch-all placed first hides every rule after it.
2. **Why isn't `doReport` in `$allowed_actions`?**
   It is a form action. Requests reach it through the form (`ReportForm`), which only allows actions it defines.
3. **How does Silverstripe protect forms from CSRF?**
   A per-session `SecurityID` token is added to each form and checked on submit.
4. **What does `saveInto()` protect against?**
   Mass assignment: only fields defined on the form are written to the record.
5. **Why is the report form rendered outside `<% with $Stock %>`?**
   Inside `with`, lookups go to the stock; `ReportForm` is a controller method.
6. **Why not rank search results with raw SQL?**
   It would put user input into SQL text; ORM filters keep it parameterised.
7. **301 or 302 for `/stocks/sndl` → `/stocks/SNDL`?**
   301: the lower-case URL is permanently the same resource as the canonical one.
